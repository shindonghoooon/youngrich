# 종목 분석 프로젝트

케이스별로 검증된 대가의 로직을 하나씩 이식해 종목을 판정한다.
만능 프레임워크는 만들지 않는다.

## 시작하기

새 대화에서 `PROJECT.md` 를 첨부하고 시작한다. 현재 상태와 다음 할 일이 거기 있다.

## 구조

| 경로 | 내용 |
|---|---|
| `PROJECT.md` | **운영 지침.** 케이스 지도·규칙·현재 상태 |
| `cases/01-lynch.md` | 케이스 1 확정판 (흑자 성장주) |
| `data/watchlist.json` | 종목별 등급·스토리·추적항목 (기계 판독용) |
| `data/ledger.csv` | 결과 원장. 판정 시점가 기록 → 사후 검증 |
| `tools/` | 수집·판정 스크립트 |
| `.github/workflows/daily.yml` | 평일 07:00 KST 자동 감시 |

## 산출물

```
① 등급  A/B/C/D/X
② 총평  등급 근거 + 등급을 바꿀 단일 사건
③ 추적  1~3개 (항목/확인처/승격조건/강등조건)
```

가격(진입가·손절가·목표가)은 내지 않는다.

## 케이스 지도

| # | 케이스 | 로직 | 상태 |
|---|---|---|---|
| 1 | 흑자 성장주 | 피터 린치 | 확정 |
| 2 | 경기순환주 | 린치 순환주 + 보완 | 다음 |
| 3 | 적자 성장주 | 베일리 기포드 10문항 | 대기 |
| 4 | 신규상장 | 미정 | 미착수 |

## 도구

```bash
python tools/watch.py       # 일일 감시 (변화 있을 때만 출력)
python tools/prediag.py STRL # 사전진단
python tools/peg.py          # 3년 EPS CAGR PEG
```

## 원칙

- 한 번에 케이스 하나
- 로직 동결 중 수정 금지 (관찰 기록에만 적는다)
- 같은 문제 2회 이상일 때만 규칙으로 승격
- 개정 시 해당 케이스 전 종목 재적용
- 버전 번호를 붙이지 않는다
